# برآورد قیمت و کنترل تولید WPC

وب‌اپ فارسی (راست‌به‌چپ، تاریخ شمسی، همه چیز به تومان) برای محاسبه قیمت تمام‌شده و قیمت فروش
محصولات WPC از روی فرمول‌ها و قیمت مواد، همراه با پارت تولید و انبار. به‌صورت PWA روی اندروید نصب می‌شود.

```
npm install
npm start        # ساخت اپ و اجرای سرور روی http://localhost:3000
npm test         # تست‌های منطق محاسبه و سرور
```

برای توسعه: در یک ترمینال `npm run server` و در ترمینال دیگر `npm run dev`.

### راه‌اندازی روی سرور

| متغیر | معنی | پیش‌فرض |
|---|---|---|
| `PORT` | پورت | `3000` |
| `DATA_DIR` | پوشه پایگاه داده SQLite (حتماً از آن نسخه پشتیبان بگیرید) | `./data` |
| `ADMIN_PASSWORD` | رمز ادمین اولیه (فقط اولین اجرا) | رمز تصادفی، در لاگ چاپ می‌شود |

کاربر اولیه `admin` است. برای نصب روی اندروید (PWA) و امنیت کوکی، سرویس باید پشت **HTTPS** باشد
(مثلاً Caddy یا nginx با گواهی). پشت پروکسی، هدر `X-Forwarded-Proto` و `X-Forwarded-For` را عبور دهید.

## راه‌اندازی با Supabase (بدون سرور اختصاصی)

پایگاه داده و ورود کاربران را Supabase می‌دهد و فقط یک سایت ایستا می‌ماند. منطق مهم (کنترل موجودی، قفل قیمت پارت،
میانگین موزون خرید، نقش‌ها) داخل خود پایگاه داده اجرا می‌شود و کاربر مستقیم به جدول‌ها دسترسی ندارد.

1. در supabase.com یک پروژه بسازید.
2. در **SQL Editor** محتوای فایل `supabase/setup.sql` را کامل بچسبانید و Run بزنید (اجرای دوباره داده را پاک نمی‌کند).
3. در **Authentication ← Users ← Add user** اولین کاربر را بسازید (Auto Confirm User را بزنید). **اولین کاربر ادمین می‌شود**؛ بعدی‌ها «مشاهده‌گر» شروع می‌کنند و ادمین در تب «کاربران» نقششان را عوض می‌کند.
4. در **Project Settings ← API** مقدار Project URL و anon public key را بردارید و در `public/config.js` بگذارید (یا در `.env` به صورت `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`).
5. `npm run build` و پوشه `dist/` را روی هر هاست ایستا بگذارید (Netlify، Cloudflare Pages، GitHub Pages، ...). برای نصب روی اندروید، هاست باید HTTPS باشد.

کلید `anon` عمومی است و مشکلی ندارد. کلید `service_role` را هرگز در اپ یا مخزن نگذارید.

تست SQL (نیاز به Postgres محلی): `PGHOST=... PGPORT=... PGUSER=... npm run test:sql`. بعد از هر تغییر در `supabase/schema.sql` یا `src/core/seed.ts`، `npm run gen:sql` را بزنید.

### نقش‌ها

- **ادمین:** همه چیز، شامل قیمت‌ها، فرمول‌ها، هزینه‌ها، کاربران و گزارش تغییرات.
- **اپراتور:** ثبت پارت، خرید و ضایعات.
- **مشاهده‌گر:** فقط لیست قیمت، موجودی و هشدارها.

دسترسی در سرور بررسی می‌شود، نه فقط در رابط کاربری.

## ساختار

- `src/core/` منطق محاسبه، بدون وابستگی به رابط کاربری (تست‌شده):
  - `flatten.ts` تبدیل فرمول تو در تو (مثل PRP داخل پروفیل) به مواد اولیه
  - `costing.ts` قیمت تمام‌شده، سربار، ضایعات، قیمت هر کیلو، متر و شاخه ۳ متری
  - `batch.ts` پارت با فرمول قابل تغییر، قیمت منجمد و گزارش انحراف از فرمول استاندارد
  - `inventory.ts` انبار با میانگین موزون، کمبود موجودی و کسر مصرف پارت
  - `validate.ts` هشدار قیمت، وزن یا هزینه ناقص
  - `seed.ts` داده اولیه از دست‌نوشته‌ها (رنگ‌ها و وزن‌ها هنوز نیاز به تأیید دارند)
- `supabase/` طرح پایگاه داده (`schema.sql`)، فایل آماده برای اجرا (`setup.sql`) و تست‌ها.
- `server/` سرور Hono با SQLite: ورود، نقش‌ها، نسخه‌بندی کاتالوگ، ثبت پارت و انبار با کنترل موجودی، گزارش تغییرات.
- `src/tabs/` صفحه‌های برنامه.
